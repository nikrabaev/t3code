# v0.2 build spec

Concrete, implementable specification for Weave v0.2 — the **parallelization slice**. This is where the core Weave thesis gets validated: concurrent Node dispatch with conflict-free execution under V1–V4, scope enforcement via Claude Code's native hook mechanism, and merge-drivers for shared-surface files. Read [concepts.md](concepts.md), [architecture.md](architecture.md), [t3code-integration.md](t3code-integration.md), and [v0.1-spec.md](v0.1-spec.md) first — v0.2 builds strictly on v0.1's foundation.

## What v0.2 is

- Parallel scheduler dispatching N ready Nodes concurrently (N = `concurrencyCap`), gated by write-set disjointness.
- Claude Code `PreToolUse` hooks enforcing per-Node Scope before tool calls execute.
- Merge-driver infrastructure with one implementation for `package.json`; lockfile regenerated post-merge.
- React Flow DAG canvas replacing v0.1's grouped-by-Phase list.
- Live concurrency slider + Pause control in the header.
- Auto-subdivide on node failure (within pre-authorized policy).
- PendingDecision scheduler-gating scaffold (dormant; v0.3 lights it up).

## What v0.2 is **not**

Still deferred. Ships in v0.3+:

- Full PendingDecision mechanics — auto-resolver reactor, `weave.decision.surface` event, pre-authorization DSL, decision-queue sidebar UI.
- Redesign mode in the Weave composer (user-initiated Blueprint amendments).
- Phase gate smoke tests + approval modal, "Chat before deciding."
- Node-level pause / resume / restart for user-initiated intervene.
- Auto-concurrency mode (Auto setting on the slider that adapts to subscription rate-limit usage).
- Blueprint version *diff* overlay on canvas (just a version badge in v0.2; real diff UX ships with Redesign).
- Observability panel detail (cost meter, per-Node token charts).

## Decisions locked (Q1–Q7 summary)

These are the design calls that closed during the 2026-04-21 planning conversation. The rest of the spec assumes them.

### Q1 — Scope enforcement

Use Claude Code's native **`PreToolUse` hook**, configured per-Node via `.claude/settings.local.json` written into each Node's worktree before dispatch. Hook callback points at a Weave-side validator that checks the tool call against the Node's declared `writeSet`. Reject blocks the tool call and emits a `weave.node.scope-violation` audit event. Belt-and-suspenders: set Claude Code permission mode conservatively (no auto-accept outside the worktree).

### Q2 — Concurrent sessions

Each Node runs in its own `claude` CLI subprocess, spawned via t3code's existing `ClaudeAdapter`. Concurrency is process-level. All concurrent Nodes share the user's subscription rate limit, so default `concurrencyCap` is 2; rate-limit errors trigger per-Node exponential backoff.

### Q3 — Worktree merge-back

**Layer-by-layer merge on the fly.** When all Nodes in a topological layer verify, Weave merges them into the Run's integration branch in deterministic order (node-id lexicographic). V1 guarantees conflict-freedom; if a conflict does occur, it's a scheduler bug — log and abort the Run.

### Q4 — Merge-driver scope

One `MergeDriver` primitive with one registered implementation: `package.json` (union-merge of dependency objects). Lockfile regeneration is a post-merge scheduler action, not a merge-driver. `.gitignore` uses the same "append-if-missing" mechanism as a quick extension if needed. Everything else is Hoist or Stitch (Integration Nodes).

### Q5 — Concurrency-cap changes mid-run

Cap range `[1, 8]`, default `2`. In-flight Nodes always finish. Lowering takes effect on next scheduling decision. Raising immediately dispatches ready Nodes up to the new cap. Cap changes emit `weave.run.concurrency-cap-updated` (lightweight, not a Blueprint version bump). Pause is a separate control (not concurrency=0).

### Q6 — Failure escalation

**Auto-subdivide within pre-authorized policy**, default: *"retry once → subdivide once → escalate."* Subdivide invokes the planner with a narrow prompt to replan the failed Node into a micro-DAG; output replaces the Node with `compiledBy: "auto-subdivide"` as a new Blueprint version. Every subdivide event goes to the auto-decision log. Depth limit: one subdivide per original Node. If the planner fails to produce a valid subdivide micro-DAG, skip to escalate.

### Q7 — PendingDecision gating scaffold

Scheduler readiness check includes "all attached decisions resolved." `openDecisions` is maintained in the projection. That's all — the v0.2 planner continues to emit zero decisions, so the gating path is dormant in production and tested only with synthetic fixtures. Auto-resolver, surface events, pre-auth DSL, and UI all stay v0.3.

## Slice 2 — Scope enforcement (PreToolUse hook infrastructure)

The slice that makes parallel execution *safe* by preventing out-of-scope writes. All in `apps/server/`.

### 2.1 Files

| File | Purpose |
|---|---|
| `apps/server/src/orchestration/Services/WeaveHookServer.ts` | HTTP endpoint (or Unix socket — see §2.3) that receives hook callbacks |
| `apps/server/src/orchestration/Services/WeaveHookValidator.ts` | Pure function: `(nodeScope, toolCall) => AllowOrReject` |
| `apps/server/src/orchestration/Layers/WeaveHookInstaller.ts` | Writes `.claude/settings.local.json` into a worktree before dispatch |
| `apps/server/src/orchestration/Services/WeaveHookTelemetry.ts` | Receives scope-violation signals, emits `weave.node.scope-violation` events |
| `apps/server/src/orchestration/Services/WeaveHookValidator.test.ts` | Unit tests for the validator |
| `apps/server/src/orchestration/Layers/WeaveHookInstaller.test.ts` | Integration test that spawns a real `claude` CLI pointed at a fixture worktree and verifies the hook fires |

### 2.2 Validator logic

Pure function. Given:

- The Node's `Scope { readSet, writeSet }`.
- The tool call (name, arguments — specifically `file_path` for Write/Edit, `command` for Bash).

Return:

```ts
type HookDecision =
  | { decision: "allow" }
  | { decision: "deny"; reason: string }
```

Rules:

1. **Read-only tools** (Read, Grep, Glob) — always allow.
2. **Write tools** (Write, Edit, NotebookEdit) — the `file_path` must match the `writeSet` as a glob pattern (use `micromatch` or equivalent; t3code's `shared/git` utilities may already have glob helpers).
3. **Bash** — always allow in v0.2. Fine-grained Bash scope enforcement is v0.3+. (The worktree boundary already constrains Bash to the worktree.)
4. **Unknown tools** — default deny, log telemetry.

### 2.3 Hook server mechanics

Claude Code `PreToolUse` hooks invoke a shell command with the tool call on stdin and read a decision from stdout. Two viable implementations:

- **(a) HTTP endpoint**: Weave server runs a local HTTP endpoint bound to `127.0.0.1:$PORT`. The hook script is `curl localhost:$PORT/weave-hook/{runId}/{nodeId}` with the tool-call JSON piped. Weave server decodes, validates, responds. Simple.
- **(b) Unix socket / IPC file**: shell script reads from a per-Node socket. More fiddly on Windows; skip for v0.2.

**Recommend (a)** — HTTP endpoint. Local-only, low latency, trivial to test.

The per-Node `.claude/settings.local.json` contains:

```jsonc
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit|NotebookEdit|Bash",
        "hooks": [
          {
            "type": "command",
            "command": "curl -s -X POST -H 'Content-Type: application/json' --data @- http://127.0.0.1:$WEAVE_HOOK_PORT/weave-hook/{runId}/{nodeId}"
          }
        ]
      }
    ]
  }
}
```

`$WEAVE_HOOK_PORT` is injected into the child subprocess's environment when the `ClaudeAdapter` spawns it.

### 2.4 Installer

The installer writes `.claude/settings.local.json` into the worktree (not the parent repo — this is a per-Node local config) before `claude` is spawned. It also tears down the file if needed (though `.claude/settings.local.json` is git-ignored by default in Claude Code conventions, so it doesn't leak into commits).

### 2.5 Integration test

The test spawns a real `claude` CLI process (or a stub that simulates its hook invocation behavior) pointed at a fixture worktree with a declared write-set `["src/allowed/**"]`. Issues a write to `src/allowed/foo.ts` — expect allow. Issues a write to `src/forbidden/bar.ts` — expect deny. Verifies the `weave.node.scope-violation` event fires in the second case.

(Mocking Claude Code's hook-invocation path is acceptable if a live-CLI test is too slow for CI; the contract is what the hook handler expects on stdin and returns on stdout.)

### 3.2 Scheduler parallel dispatch

New state machine (replaces v0.1's sequential loop):

```
loop:
  ready = computeReadySet(currentBlueprint, projection)
           // ready = { N | ancestors all verified
           //             AND decisions all resolved         // ← Q7 gating
           //             AND N.status == "pending" }
  running = {N | N.status == "running"}

  while |running| < concurrencyCap AND ready is non-empty:
    candidate = pick from ready respecting V1 (disjoint writeSet with running)
    if candidate is None: break   // V1 blocks further dispatch this round
    dispatch(candidate)
    running += {candidate}; ready -= {candidate}

  wait for next event: {node verified, node failed, cap changed, pause, resume}
  handle event; goto loop
```

V1 check: pick the first ready Node whose `writeSet` is pairwise disjoint with all currently-running Nodes' write-sets. If none is, block and wait (some running node will finish and unblock).

### 3.3 Layer-merge trigger

After each `weave.node-verified`, check: *"Is this the last Node in its layer, considering only Nodes that were dispatched from this Blueprint version?"* If yes:

1. For each file touched by any Node in the layer:
   - If exactly one Node wrote it → standard git merge (fast-forward).
   - If multiple Nodes wrote it (should be only shared-surface files per V1/hoisting) → invoke the `MergeDriver` for that file.
2. After all files merged → if any was a `package.json`, regenerate the lockfile at the integration branch (`bun install --frozen-lockfile=false`).
3. Emit `weave.layer-merged` event.

### 3.4 MergeDriver registry

```ts
interface MergeDriver {
  matches(filePath: string): boolean
  merge(targetContent: string, incomingContents: string[]): string
}
```

v0.2 ships **one** implementation:

```ts
const PackageJsonMergeDriver: MergeDriver = {
  matches: (p) => p.endsWith("/package.json") || p === "package.json",
  merge: (target, incoming) => {
    // Parse all; union dependencies / devDependencies / peerDependencies objects.
    // Take target's other fields (name, version, scripts) unchanged — incoming
    // Nodes shouldn't have modified them under V1.
    // If they did: emit a V1 violation and abort.
  }
}
```

Registry wires the one driver. Designed for extension — adding `.gitignore` append-if-missing later is a new `MergeDriver` entry.

### 3.5 Subdivide reactor

Watches `weave.node-failed` events. When a failure crosses the retry threshold:

1. Check subdivide depth — if this Node was itself produced by a prior subdivide (check Blueprint history), skip to escalate.
2. Check per-Run policy — if user opted out of subdivide, escalate.
3. Invoke `WeavePlanner` with scoped prompt: *"Replan only this Node into a micro-DAG that satisfies its original Contract. Existing siblings and descendants must remain compatible. Respect V1–V4."*
4. Validate the returned micro-DAG:
   - Schema validates as a `Blueprint` fragment.
   - Every micro-Node's Scope is a subset of the original Node's Scope.
   - Micro-DAG doesn't introduce new PendingDecisions (v0.2 planner constraint).
5. If valid → emit `weave.blueprint-compiled` with `compiledBy: "auto-subdivide"`, replacing the failed Node with the micro-DAG. Log to auto-decision log.
6. If invalid → escalate.

### 3.6 PendingDecision gating scaffold

In `computeReadySet`: filter out Nodes whose `attachedDecisions` intersect with `openDecisions`. In v0.2 this is dead code (planner emits zero decisions). Unit test with a synthetic Blueprint that has one decision blocking one node — verify the node doesn't enter the ready set, resolve the decision, verify it does.

### 3.7 Run-level Pause and cap changes

- `weave.run.pause` sets `run.isPaused = true`. Scheduler main loop checks the flag at the top and waits. In-flight Nodes keep running; they don't get interrupted.
- `weave.run.resume` clears the flag; scheduler wakes up.
- `weave.run.set-concurrency-cap` updates `run.concurrencyCap` and wakes the scheduler (which may immediately dispatch if the cap increased).

### 3.8 Tests

Integration-level via an in-memory fixture:

- **Parallel dispatch**: a 3-sibling Blueprint with `concurrencyCap=3` — verify all three dispatched concurrently.
- **V1 enforcement**: a Blueprint where two ready Nodes have overlapping write-sets — verify only one is dispatched, the other waits.
- **Cap change**: start with cap=2, 2 running, drop to 1, one completes — verify no new dispatch until running drops to 0; raise to 3 with 2 pending — verify both dispatch.
- **Pause/Resume**: pause during 2-running → resume → verify resume triggers dispatch of next ready.
- **Subdivide**: a Node fails twice → reactor invokes planner → Blueprint gets a new version with `compiledBy: "auto-subdivide"` → scheduler dispatches the micro-DAG.
- **Subdivide failure**: planner returns invalid micro-DAG → escalate.
- **Decision gating**: synthetic Blueprint with one pending decision blocking a ready node → verify gating.
- **Layer merge**: two sibling Nodes both edit `package.json` → verify `PackageJsonMergeDriver` unions their deps → verify `weave.layer-merged` event.
- **V1 violation safety net**: force a malformed Blueprint that violates V1 → verify `weave.scheduler.v1-violation` event and Run aborts.
